# gonote 디자인 근거

> 수치를 지어내지 않는다. 아래 값은 **godo·gosay 에서 이미 레퍼런스를 열어 재 둔 것**이거나,
> 이 프로젝트에서 **브라우저로 직접 잰 것**이다. 어느 쪽인지 표에 적었다.

## 방향

**받아적는 화면은 대화창, 회의록은 문서.** 한 앱에 성격이 다른 두 화면이 들어 있고, 일부러 그렇게 뒀다.

- **받아적기** — 카톡과 같은 모양이다. 기록이 위로 쌓이고 입력이 아래에 고정된다.
  교회에서 쓰는 앱이라 카톡과 같은 모양이면 설명할 것이 없고, 엄지가 닿는 자리에 입력이 온다.
- **회의록** — 종이 문서다. 흰 면 위에 제목·구분선·표가 있고, 그대로 인쇄된다.
  교회에 제출하거나 보관하는 기록이라 "앱 화면" 처럼 보이면 안 된다.

| 값 | 무엇 | 어디서 |
| --- | --- | --- |
| 반경 10 / 14 / 20 / 26 / 알약 | 카드·면·틀·버튼 | godo 실측 (gif.garajedeideas.com 전수 집계) |
| 120ms / 200ms / 320ms | 미세 반응 / 주력 / 넓은 이동 | godo 실측 |

| 자간 부호 반전 | 본문은 조이고(-0.016em) 큰 제목은 벌린다(+0.008em) | Apple SF Pro 트래킹 표 |
| 그림자 대신 채움색 | 얹힌 면은 색으로, **뜬 것만** 그림자로 | godo 실측 |
| `--muted: #636368` 등 명암비 안전색 | 작은 글자 | gosay 에서 axe 로 실측해 고친 값 |

## 이 프로젝트에서 직접 잰 것

| 잰 것 | 결과 | 어떻게 |
| --- | --- | --- |
| 터치 영역 | 44px 미만 **0곳** | `node scripts/check-taps.mjs` — 6화면 + 줄 고치기 칸까지 전수 |
| 가로 넘침 | 320/375/390/768/1024/1440 전부 **0px** | `node scripts/shoot.mjs`, E2E |
| 명암비 | axe 라이트·다크 위반 **0건** | `pnpm e2e` (wcag2a + wcag2aa + wcag21aa) |
| 인쇄 레이아웃 | A4(794×1123) 한 장에 머리~할 일까지 들어간다 | `node scripts/shoot.mjs` 의 `15-인쇄-A4` + `check-live.mjs` 가 인쇄 미디어로 높이를 잰다 |

### 스크린샷이 찾아낸 것 (테스트는 전부 통과하고 있었다)

| 무엇 | 어떻게 보였나 | 원인 |
| --- | --- | --- |
| 받아적기 입력 독 | 종류 5칸 중 2칸과 '넣기' 버튼이 **없었다** | 격자 칸의 기본 `min-width: auto` 가 칸을 화면 밖으로 밀어냈고, `.cap` 의 `overflow: hidden` 이 그걸 조용히 잘랐다 |
| 회의록 결정 | **번호가 안 보였다** | `base.css` 가 모든 목록의 표식을 지운다. 결정은 번호가 있어야 카톡에서 "2번" 으로 가리킨다 |
| 회의 일시 | `~01:40` 으로 깨져 보였다 | 폐회만 있을 때의 꼴을 안 만들어 뒀다 → `timeLabel()` 로 통일 |
| 인쇄본 | 일시·장소 라벨에 **초록 알약 배경**이 찍혔다 | `.paper__done` 규칙이 인쇄 블록의 선택자 목록 한가운데로 들어가 라벨들이 그 스타일을 받았다. 화면에서는 멀쩡했다 |

## 줄 종류의 색

회의록에서 눈이 먼저 가야 하는 것은 **결정과 할 일**이다. 그래서 다섯 종류 중 둘만 색을 준다.

| 종류 | 색 | 왜 |
| --- | --- | --- |
| 결정 | `--decision-ink` (짙은 녹색) | 회의의 결과다. 문서에서 가장 눈에 띄어야 한다 |
| 할 일 | `--action-ink` (짙은 호박색) | 사람이 가져가는 것. 결정 다음으로 중요하다 |
| 보고 | `--report-ink` (짙은 파랑) | 사실·숫자. 구분은 되되 앞의 둘을 누르지 않는다 |
| 발언 | 회색 글자 | 양이 가장 많다. 색을 주면 문서가 알록달록해진다 |
| 메모 | 회색 면 | 회의록에 나가지 않는다. 화면에서만 다르게 보인다 |

세 색 모두 **옅은 틴트 위에 올라가므로 `--ok`/`--warn`/`--p3` 를 그대로 쓰면 명암비가 3.6~3.8 로
AA 에 못 미친다.** gosay 에서 실측해 만든 짙은 짝을 그대로 가져왔다.

## 일부러 안 한 것

- **독(탭 바)** — 화면이 셋뿐이고(목록 ↔ 받아적기 ↔ 회의록) 서로 안에서 길이 있다.
  독을 두면 받아적는 화면에서 입력칸이 그만큼 올라간다
- **줄이 들어올 때의 애니메이션** — 회의 중에 100줄이 들어온다. 매번 움직이면 눈이 피곤하다
- **본문 글꼴을 명조로 바꾸기** — 문서다움은 명조가 가장 쉬운 길이지만, iOS 에 믿을 만한
  한글 명조가 번들돼 있지 않다. 내일 아침 회의에 글꼴을 거는 것은 위험해서 Pretendard 로 두고
  **크기·간격·구분선**으로 문서다움을 만들었다. 다시 한다면 여기부터다
- **새 레퍼런스 전수 집계** — 이번 밤에는 하지 않았다. godo 의 실측값이 그대로 유효하고,
  시간을 3단계 배포와 인쇄 레이아웃에 썼다. 다시 한다면 **종이 회의록 서식**(교단 별지 양식 PDF)을
  열어 여백·제목 크기·표 괘선 두께를 재는 것부터다
